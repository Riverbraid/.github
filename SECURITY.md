# Security Policy

This security policy defines how to report security concerns for Riverbraid public repositories.

It is a public coordination surface only. It does not create a security certification, legal guarantee, response-time guarantee, staffed support obligation, production readiness claim, or external audit claim.

## Supported scope

Security reports may concern visible Riverbraid repositories, documentation, verification surfaces, release artifacts, or public metadata.

The current public canonical verification entry point is:

```text
Riverbraid-Evaluation-Kit
```

## Reporting a concern

Use a GitHub issue in the relevant repository when the concern is public and does not expose secrets, private keys, credentials, exploit instructions, or sensitive personal information.

For sensitive reports, do not publish secrets, private credentials, or exploit material in public issues.

If private reporting infrastructure is later established, this file should be updated with the exact private contact path.

## What to include

A useful report should include:

- repository name
- affected file or surface
- observed behavior
- expected behavior
- reproduction steps when safe to share
- reason the issue may affect security, integrity, verification, or public trust

## Evidence boundary

This policy does not claim:

- guaranteed response time
- professional security support
- third party audit
- vulnerability bounty program
- production readiness
- absolute security
- absence of defects
- legal review

## Maintenance

Update this policy when Riverbraid's reporting surface, ownership model, or public support capacity changes.
